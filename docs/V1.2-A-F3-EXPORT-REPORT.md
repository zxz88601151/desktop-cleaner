## 0. 摘要

在 Feature 2 的 `AnalysisResult` 之上新增**导出报告**能力：**JSON + CSV** 双格式，UTF-8，稳定字段，显式语义。

- **纯逻辑层先行**：`core/report.py` 无 Qt、无 UI 依赖，只读 `AnalysisResult` 并写出调用者指定的**一个文件**。
- **稳定字段 + 显式单位**：字节字段一律 `_bytes` 后缀；时间字段一律 `_epoch`（Unix 秒）+ ISO-8601 字符串；不做任何本地化格式化。
- **不使用 UI 文案作为数据结构**：类别以**稳定 key**（`images` / `documents` …）导出；中文标签放在独立的 `category_labels` 块中，**明确定义为显示辅助**，不是记录身份。
- **溯源完备**：每份报告都带 `schema` / `generated_at`(+epoch) / `app_version` / `rules_version`（规则内容指纹）/ `rules_count`，任何一份报告都能回溯到产生它的规则集。
- **CSV 是一张严格 RFC-4180 表**：异构分区共用一套表头 + `section` 列，而不是拼接伪分区，保证机器可解析。

## 1. AUDIT

| 问题 | 结论 |
|---|---|
| 是否已有导出能力？ | **无**。全仓无任何 CSV / JSON 导出代码（`rules.py` 里的 `csv` 只是扩展名规则）。 |
| 能否复用 `AnalysisResult.to_dict()`？ | **能**。Feature 2 已设计为导出友好（稳定字段 + `_bytes` 单位），本功能直接消费，零改造。 |
| 报告需要哪些"规则"信息？ | 需要能回答"这份报告是用哪套规则生成的"。当时**无**规则指纹机制。 |
| 规则指纹放哪？ | `core/rules.py` 新增纯函数 `rules_fingerprint()`（**纯增量**，不改既有逻辑），Feature 4 也将复用。 |
| CSV 如何承载异构表？ | 三种方案对比：① 多文件（N 个 CSV）；② 单文件堆叠伪分区；③ 单文件长表 + `section` 列。**选 ③**：单文件、严格 CSV、机器可解析。 |
| 中文 CSV 在 Excel 打开乱码？ | 是。中文 Windows + Excel 需 **BOM**。故 CSV 用 `utf-8-sig`（仍是合法 UTF-8），JSON 用纯 UTF-8。 |
| UI 弹窗如何做冒烟？ | 打桩 `QFileDialog.getSaveFileName` + `QMessageBox.exec`，其余走**真实**生产路径。 |

**AUDIT 结论：无既有实现可复用；但数据模型已就绪，本功能为纯新增的只读写出层，无新文件操作通道。**

## 2. DESIGN

### 2.1 报告文档（JSON）

```jsonc
{
  "schema": "desktop-cleaner.report.v1",
  "generated_at": "2026-09-29T10:11:12+00:00",
  "generated_at_epoch": 1759...,
  "app_version": "1.1.1",
  "rules_version": "rules-0e08433df3ca-104",
  "rules_count": 104,
  "analysis": { /* AnalysisResult.to_dict()，字段名稳定、单位显式 */ },
  "category_labels": { "images": "图片", ... },   // 仅显示辅助
  "notes": {
    "size_unit": "bytes",
    "time_unit": "unix_epoch_seconds",
    "scope": "read-only analysis; no file was created, moved or deleted",
    "empty_folder_semantics": "...",
    "category_key_semantics": "...",
    "csv_encoding": "UTF-8 with BOM"
  }
}
```

**语义显式化**：单位、时间基准、空文件夹口径、类别键语义、CSV 编码全部写在 `notes` 里，报告自带说明书。

### 2.2 CSV（单张严格表）

表头（固定 8 列）：
```
section,item,count,size_bytes,folder_count,path,mtime_epoch,value
```

| section | item | 其余列 |
|---|---|---|
| `summary` | 指标名（`total_size_bytes` / `file_count` / `schema` / `rules_version` / `generated_at` …） | `value` |
| `category` | **稳定 key** | `count`、`size_bytes` |
| `extension` | 扩展名（无扩展名 → `(none)`） | `count`、`size_bytes` |
| `largest_file` | 排名 | `size_bytes`、`path`、`mtime_epoch` |
| `largest_folder` | 排名 | `count`(直接文件数)、`size_bytes`(子树)、`folder_count`(直接子目录)、`path` |
| `recent_file` | 排名 | `size_bytes`、`path`、`mtime_epoch` |
| `empty_folder` | 排名 | `path` |

- 行终止符 `\r\n`（RFC-4180）；`utf-8-sig`（UTF-8 + BOM）。
- 数字以 `int` 写入 → 不加引号 → Excel 直接识别为数值。

### 2.3 规则指纹

```python
rules_fingerprint(rules) -> "rules-<sha1(content)[:12]>-<rule_count>"
```
内容决定：同一套规则恒等；增 / 删 / 改任一映射即变。报告中记录该值，使报告可跨版本 / 跨用户规则集比对。

### 2.4 分发

```python
export(result, path, *, app_version, rules=None, generated_at=None) -> Path
```
按**后缀**分发（`.json` / `.csv`，大小写不敏感）；其他后缀抛 `ValueError`（含支持格式提示）。

## 5. 已知限制

- **CSV 为长表格式**：异构分区共用一套表头，未为每个分区生成独立 CSV（有意：保持"单文件、可解析"）。
- **不含完整文件清单**：导出的是分析结果（含 top-N 排行），不是逐文件全量清单——避免为百万文件生成巨型 CSV。
- **无 HTML 格式**：本期只做 JSON + CSV（最低要求）；HTML 留待后续。
- **同步导出**：报告体积由 top-N 决定（很小），故同步写出，未走 Worker。
- **`category_labels` 为中文**：当前仅提供中文标签映射；多语言留待后续。
