## 0. 摘要

在既有 **移动引擎 / 规则 / 数据库 / 撤销 / 历史 / 安全模型** 之上，新增"空文件夹清理"能力。**没有**新建任何文件操作通道：

- 检测（`find_empty_folders`）只读、保守，且**只报最外层空文件夹**（maximal subtree）。
- "清理"实际是**移动到同一根目录下的隔离夹** `_待清理空文件夹`，由既有 `core.organizer.move_items` 执行，全程记账、可撤销。
- 任何无法**证明**安全的路径（隐藏 / 系统 / junction / symlink / reparse point / 权限拒绝）一律不报。
- 执行前对每个目录做 **TOCTOU 复检**：扫描后新增内容的目录**跳过、绝不静默删除**。

---

## 1. AUDIT（现状调研）

| 问题 | 结论 |
|---|---|
| 是否已有空目录能力？ | 无。`scanner.py` 只扫文件；`organizer.py` 只移动文件。 |
| 移动引擎可复用？ | 可。`core.organizer.move_items(items, on_progress)` 接受任意 `PlanItem(source, target, category)`，碰撞自动改名，两阶段 DB 记账。 |
| 撤销可复用？ | 可。`ui/undo.py` 按 `operations` 表还原；只需把隔离夹加入"清理后空目录"名单。 |
| 隐藏/系统判定可复用？ | 可。`scanner._is_hidden`（`GetFileAttributesW`）。 |
| 长路径可复用？ | 可。`utils.paths.win_long`（≥240 字符加 `\\?\`）。 |
| 风险点 | junction/symlink/reparse 会导致**误删链接目标**；必须显式排除。 |

**AUDIT 结论：能力可在现有安全模型内实现，无需新引擎。**

## 2. DESIGN

### 2.1 数据模型

```python
@dataclass
class EmptyFolder:
    path: Path      # 最外层空文件夹
    nested: int     # 随它一起被移动的子孙目录数
    mtime: float

@dataclass
class CleanupResult:
    planned: int
    moved: int
    failed: int
    stale: List[str]        # 扫描后新增内容、被跳过的目录（TOCTOU）
    result: Optional[OrganizeResult]
```

### 2.2 检测语义（保守）

- 一个目录只有在**整棵子树不含任何文件**时才算空。
- **只报最外层**：一旦某目录为空，其子孙记录被丢弃（外层已覆盖它们，且避免隔离夹目标冲突）。
- 遇到**任一**非目录条目（文件/符号链接）、**受保护**子项、或**不可读** → 该目录判定为"非空"，其祖先同样非空。
- **关键正确性约束**：遍历遇到内容时**只标记 `has_content=True` 并继续**，绝不 `break`——否则会漏掉同级后续的空目录（实现期曾出现该 bug，见 §5）。

### 2.3 安全闸门（`_is_protected`）

| 类别 | 判定 |
|---|---|
| 隔离夹自身 | 排除（防递归清理） |
| Windows 系统目录 | `system volume information` / `$recycle.bin` / `$winreagent` / `recovery` / `config.msi` / `windows` / `windowsapps` |
| 隐藏 | `scanner._is_hidden` |
| junction / symlink / mount point | `os.path.islink` + `FILE_ATTRIBUTE_REPARSE_POINT (0x400)`；**无法判定 = 不安全** |
| 应用自身数据目录 | `find_empty_folders` 直接 `ValueError`（P0-4 复用） |

### 2.4 执行语义

```
plan_cleanup : 每个目录 → <root>/_待清理空文件夹/<relpath>
cleanup      : 逐项 _still_empty() 复检 → move_items() 真实移动 → 记账
```

- `_still_empty` 复用 `_walk`，与检测**同语义**（只含空目录的子目录仍算空）。
- 移动失败 / 跳过均如实进入 `CleanupResult`，不隐藏。

## 5. 实现期发现并修复的真实缺陷

| # | 缺陷 | 影响 | 修复 |
|---|---|---|---|
| 1 | `_walk` 遇到文件/受保护项时 `return (False,0,[])`，**丢弃**同级已记录的空目录 | 漏报 | 改 `has_content=True; continue` |
| 2 | 后续 `return (False,nested,recorded)` 仍会**中断循环**，跳过同级后续空目录 | 漏报 | 同上（永不中断循环） |
| 3 | 测试用 `SetFileAttributesW(...,0x2)` 未含 `0x10 (DIRECTORY)` | 隐藏位未设上 | 改 `0x2 \| 0x10` |
| 4 | `_still_empty` 用"无条目"语义 vs 检测用"传递空"语义，不一致 | 误判 stale | `_still_empty` 改为复用 `_walk` |

---

## 6. 已知限制

- **不递归到受保护子树内部**：若某目录含隐藏子目录，该目录整体不报（保守，符合安全优先）。
- **仅同根隔离**：隔离夹位于扫描根内，跨盘清理需分次。
- **首版不含"空文件"清理**：只处理空目录（0 字节文件属 Feature 3/后续议题）。
- **未做后台持久化调度**：为一次性交互任务，未接入自动化。
- **TOCTOU 窗口**：复检与移动之间仍有极小竞态，但因是"移动"而非"删除"，最坏结果只是移走一个刚写入文件的目录，且可撤销——**无数据丢失风险**。
