## 0. 摘要

新增**只读**的文件夹结构分析能力：总大小 / 文件数 / 目录数 / 类型分布 / 最大文件 / 最大目录 / 最近文件 / 空文件夹。

- **数据模型先行，UI 后置**：先产出纯逻辑 `core/analysis.py` + 11 个单元测试，再接 UI。
- **零写入路径**：`analysis.py` 中不存在任何创建 / 移动 / 删除文件的代码。分析不可能改变文件系统状态。
- **稳定键，不用 UI 文案**：`by_category` 以稳定 category key（`images` / `documents` …）为键，中文标签由 UI 侧 `core.rules.category_display` 映射——满足"不要用 UI 文案作为数据结构"，也为 Feature 3 导出铺路。
- **复用**：分类走 `core.classifier` / `core.rules`；空文件夹走 `core.empty_folders.find_empty_folders`（与"空文件夹清理"永远一致）；长路径走 `utils.paths.win_long`。

## 1. AUDIT

| 问题 | 结论 |
|---|---|
| 是否已有分析能力？ | 无。`scanner.scan` 只做"按类别分组 + 总大小"，没有目录树结构、没有最大目录 / 最近文件 / 目录计数。 |
| 能否复用 `scanner`？ | 部分。`ScanResult` 有 `sizes`（PHASE 1.2 加的逐文件字节），但**不统计目录**，且会跳过隐藏 / 系统文件与已整理输出目录——用于"分析"会失真。 |
| 目录计数 / 子树大小从哪来？ | 需新写遍历。 |
| 隐藏文件是否计入？ | **计入**。分析要反映真实占用，隐藏文件（`.git`、缓存等）同样占空间；这使分析口径与"整理扫描"口径**有意不同**，已在文档中显式声明。 |
| junction / symlink 风险？ | 会**死循环 / 重复计数**。必须显式跳过。 |
| 空文件夹口径如何统一？ | 复用 `find_empty_folders`（保守口径），避免"分析说有、清理说没有"的分歧。 |
| 递归深度风险？ | 递归实现会撞 Python 递归上限。改用**显式栈迭代遍历**。 |

**AUDIT 结论：需新模块，但可完全在既有安全模型内实现，无新文件操作通道。**

## 2. DESIGN

### 2.1 数据模型（导出友好）

```python
@dataclass
class FileEntry:      path, size, mtime
@dataclass
class FolderEntry:    path, total_size, file_count, folder_count
@dataclass
class AnalysisResult:
    root, total_size, file_count, folder_count
    by_category: Dict[str, int]          # 稳定 key -> 文件数
    by_category_size: Dict[str, int]     # 稳定 key -> 字节
    by_extension: Dict[str, int]         # 扩展名 -> 文件数
    by_extension_size: Dict[str, int]    # 扩展名 -> 字节
    largest_files: List[FileEntry]       # top N by size
    largest_folders: List[FolderEntry]   # top N by subtree size
    recent_files: List[FileEntry]        # top N by mtime
    empty_folders: List[str]
    skipped: int                         # 不可读 / 链接项
    duration_ms: int
```

- `AnalysisResult.to_dict()` 输出**稳定字段名 + 显式字节单位**（`total_size_bytes`、`size_bytes`），`json.dumps` 直接可用（测试 [11] 锁定）。
- 无扩展名归入稳定键 `"(none)"`，不写中文。

### 2.2 算法

1. **单次迭代遍历**（显式栈，非递归）：收集每个目录的直接文件数 / 直接子目录数 / 直接字节数，以及全部文件条目。
2. **一次内存折叠**：因为子目录总是在其父目录之后被发现，`reversed(dirs)` 即为合法的**后序**；据此把直接大小折叠为**整棵子树大小**。无递归 → 无路径深度上限。
3. **reparse point 不跟随**：junction / symlink / mount point 跳过并计入 `skipped` → 不会死循环、不会重复计数。
4. **不可读目录**：计入 `skipped` 并继续，绝不中断整体分析。

### 2.3 口径决策（显式声明）

| 项 | 决策 | 理由 |
|---|---|---|
| 隐藏 / 系统文件 | **计入** | 分析要反映真实占用 |
| 无扩展名文件 | 计入 `"(none)"` 桶 | 不漏统计 |
| reparse point | **不跟随**，计入 `skipped` | 防环、防重复计数 |
| 空文件夹 | 复用**保守**检测器 | 与 Feature 1 口径一致 |
| 根目录自身 | 不计入 `largest_folders`（它就是总量） | 避免冗余 |
| `folder_count` | 全部非根目录（含嵌套） | 语义明确 |

## 5. 已知限制

- **两次遍历**：`include_empty=True` 时空文件夹检测是第二次只读遍历（为保证与 Feature 1 口径一致而有意为之）。超大目录可用 `include_empty=False` 跳过。
- **无进度总量**：目录总数只有遍历完才知道，进度条为不确定态 + 已扫描目录计数。
- **`largest_folders` 含嵌套**：父子可能同时上榜（父 ≥ 子）。这是有意为之（便于定位深层大目录），未做"只留最深层"剪枝。
- **不计入隐藏文件的单独分类**：隐藏文件计入总量与类型分布，但未单列。
- **未做结果持久化**：分析结果不落库（属 Feature 3 导出范畴）。
- **`skipped` 不细分**：链接与权限拒绝合并计数。
