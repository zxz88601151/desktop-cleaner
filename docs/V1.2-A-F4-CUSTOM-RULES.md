## 0. 摘要

把"扩展名 → 类别"从**写死的内置表**升级为可定制的规则体系：

```
生效规则 = 内置规则（减去停用） + 我的规则（后者优先，同扩展名后者覆盖前者）
```

- **先做解析 / 校验层，UI 后置**：先产出纯逻辑 `core/custom_rules.py` + 15 个单元测试，再接 UI。
- **内置表运行期不可变**：定制化单独存储（settings KV 中一份小 JSON），叠加在内置表之上。`core.rules.DEFAULT_RULES` 永不被修改 → "恢复默认"天然正确，配置损坏也绝不会污染分类。
- **解析是纯函数且全域（total）**：`resolve_effective_rules()` **永不抛异常**，非法项被丢弃并记日志。校验是**独立的显式步骤**（`validate_config()`），UI 拿它提示用户，引擎则继续跑在"合法的那部分"上。
- **类别用稳定 key**：规则的类别必须是 `CATEGORY_NAMES` 的 key，绝不允许 UI 文案。

## 2. DESIGN

### 2.1 数据模型

```python
@dataclass(frozen=True)
class UserRule:                 # 一条用户规则
    extension: str              # 规范化：无点、小写
    category: str               # 稳定类别 key
    enabled: bool = True

@dataclass
class RuleConfig:               # 用户定制化（永不包含内置规则）
    disabled_builtins: List[str] = []      # 被停用的内置扩展名（规范化、去重、排序）
    user_rules: List[UserRule] = []

@dataclass(frozen=True)
class Issue:                    # 校验发现
    level: str                  # "error" | "warning"
    where: str
    message: str
```

存储：settings KV，键 `custom_rules`，值为
```json
{"version": 1, "disabled_builtins": ["pdf"], "user_rules": [{"extension": "qqq", "category": "images", "enabled": true}]}
```

### 2.2 优先级与冲突解决（已锁定）

| 规则 | 内容 |
|---|---|
| **P1** | 用户规则**恒优先**于同扩展名的内置规则（即"覆盖"）。 |
| **P2** | 用户规则之间，**后定义的胜**。UI 会阻止重复，但解析器在重复出现时仍保持确定性。 |
| **P3** | 被停用的内置扩展名从生效表中**直接缺席** → `classify` 回落到 `others`。因此"停用内置"与"覆盖为 `others`"**等价**，两者都支持。 |
| **P4** | 被 `enabled=False` 的用户规则**不参与**解析。 |

### 2.3 校验规则

| 项 | 判定 |
|---|---|
| 扩展名非空 | 空 → 错误 |
| 扩展名长度 | > 16 → 错误 |
| 扩展名字符 | 必须匹配 `^[a-z0-9][a-z0-9_+\-]*$`（字母/数字/`_`/`+`/`-`，字母或数字开头） |
| 类别合法性 | 必须是 `CATEGORY_NAMES` 的 key → 否则错误（**中文标签会被拒绝**） |
| 重复扩展名 | 用户规则内重复 → **错误** |
| 停用列表中的非内置项 | 形态合法但不在内置表 → **警告**（不阻塞） |

> **不支持复合扩展名**（如 `tar.gz`）：与 `path.suffix` 语义一致（取最后一个点之后）。已在文档中显式声明。

### 2.4 失效安全

- `RuleConfig.from_dict()` **容错**：非 dict / 字段类型错误 / 缺类别 → 逐项丢弃，退化为空配置。
- `load_config()` 遇到损坏 JSON → 记警告并返回空配置（= 纯默认），**永不抛异常**。
- 因此"配置损坏"永远不会让应用无法分类文件。

### 3.2 行为变化（用户可见）

- 侧栏新增 **「自定义规则」** 入口（图标 sliders，位于「设置」之后）。
- 页面三段：
  1. **生效规则概览**：生效条数 / 内置条数（已启用数）/ 我的规则条数 + **规则指纹** + 校验问题列表 + **「恢复默认」**（默认态自动禁用）。
  2. **我的规则**：输入扩展名 + 选类别 → 「添加规则」；每条规则可改类别、启用/停用、删除；显示 `覆盖内置` / `新增` 标记。
  3. **内置规则**：搜索框（按扩展名或中文类别名过滤）+ 逐条复选框启用/停用 + 显示"已停用 N 条"。
- **真正的生效**：整理页扫描/方案/执行、文件夹分析、导出报告的 `rules_version` **全部**改用生效规则。
  - 例：加规则 `.pdf → 视频` 后，整理页会把 `.pdf` 归入「视频」；停用 `.docx` 后，`.docx` 落入「其他」。

### 3.3 安全模型契合

| 红线 | 落地 |
|---|---|
| 不静默删除 | 只改分类映射；**不触碰任何文件** |
| 默认预览 | 规则只影响分类，扫描/预览链路不变 |
| 不绕过 Operation Engine | 规则经 `rules=` 参数进入既有引擎，未新增移动路径 |
| 不绕过业务层改 SQLite | 经 `settings_repo` 读写 |
| UI 不自实现移动逻辑 | 页面不碰文件，只编辑 `RuleConfig` |
| **不新建第二套规则系统** | 内置表保持唯一权威；定制化是叠加层 |
| 不降低 fail-safe | 解析全域；配置损坏退化为默认；非法项丢弃并记日志 |

## 5. 已知限制

- **不支持复合扩展名**（`tar.gz`）——与 `path.suffix` 语义一致。
- **内置规则不可编辑类别，只能停用**：想改内置映射，请添加一条同扩展名的用户规则（即"覆盖"，UI 会标注）。
- **无规则导入/导出**：定制化只存在本机 settings 中（`rules_version` 指纹会随分析报告导出，便于比对）。
- **无按类别批量操作**：内置规则列表逐条勾选（有搜索框）。
- **规则变更不回溯**：只影响之后的扫描 / 分析；已整理的文件不会被重新分类或移动（符合安全模型）。
- **无多规则集 / Profile**：只有一套生效规则。
